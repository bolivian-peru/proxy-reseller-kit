CONTEXT (read first)
You are updating a reseller integration built on Proxies.sx's pool gateway,
using the npm packages @proxies-sx/pool-sdk and @proxies-sx/pool-portal-react
(the "kit"). Customers each have a Pool Access Key ("pak_..."). The reseller
holds one server-side API key ("psx_...") that the kit uses on the backend.
Two changes are required:
  1. SECURITY (multi-tenant session isolation) — REQUIRED.
  2. WHITE-LABEL (hide gw.proxies.sx behind your own domain) — recommended.

Do NOT expose the psx_ API key to the browser. It is server-side only.

------------------------------------------------------------
CHANGE 1 — MULTI-TENANT SESSION ISOLATION (security, required)
------------------------------------------------------------
PROBLEM (pool-portal-react <= 0.5.x): the createPoolApiHandlers `/my-sessions`
GET + DELETE routes call `proxies.sessions.list()` / `.close()` UNSCOPED, which
returns/affects EVERY session under your reseller API key. Result: any signed-in
customer can SEE and CLOSE other customers' sessions. The fix scopes every
session call to the calling customer's own pak via the `getUserKeyId` hook.

STEP 1 — upgrade the packages:
    npm i @proxies-sx/pool-sdk@^0.6.0 @proxies-sx/pool-portal-react@^0.6.1
  (0.6.x adds per-customer scoping: sessions.list/close/closeAll accept
   { pakId }, ActiveSession gains pakKeyId, and createPoolApiHandlers threads
   getUserKeyId into all session routes automatically.)

  IF npm still shows 0.5.x (not yet published): keep your version but APPLY THE
  OVERRIDE in STEP 3 so you are protected immediately.

STEP 2 — make sure getUserKeyId is implemented and returns the CURRENT user's
pak key id (NOT the reseller's). Example (Next.js):
    createPoolApiHandlers({
      proxies,
      getSessionUserId: async () => (await auth())?.user?.id ?? null,
      getUserKeyId:     async (uid) => (await db.customers.get(uid))?.pakKeyId ?? null,
      gatewayHost: 'proxy.YOURBRAND.com',   // see Change 2
    });
  On 0.6.1 this is sufficient — the handlers now pass pakId to every session call.

STEP 3 — ONLY if you cannot upgrade yet (still on 0.5.x): override the
`/my-sessions` GET + DELETE routes with filtered versions. Replace the kit's
handlers for these paths with your own that scope by the user's pak:
    // GET /api/pool/my-sessions
    const userId = await getSessionUserId(req); if (!userId) return 401;
    const pakId  = await getUserKeyId(userId);  if (!pakId)  return {sessions:[],count:0};
    return proxies.sessions.list({ pakId });            // SCOPED
    // DELETE /api/pool/my-sessions/:key
    return proxies.sessions.close(key, { pakId });       // SCOPED (server verifies ownership)
    // DELETE /api/pool/my-sessions
    return proxies.sessions.closeAll({ pakId });         // SCOPED

VERIFY (must pass): sign in as two different customers (two different pak_ keys).
Customer A's ActiveSessionsTable must show ONLY A's sessions, and A must get
"Session not found" when trying to DELETE B's sessionKey.

------------------------------------------------------------
CHANGE 2 — WHITE-LABEL THE GATEWAY (hide gw.proxies.sx)
------------------------------------------------------------
Your customers should connect to YOUR domain, never gw.proxies.sx. The gateway
is a plain proxy on ports 7000 (HTTP) / 7001 (SOCKS5) and accepts a connection
on its IP under ANY hostname — auth is the pak_ + username, not the hostname.
So you only need DNS + one config value. No TLS cert needed on the proxy ports.

STEP 1 — DNS: add an A record (DNS-only, NOT a CDN/Cloudflare-proxied record):
    proxy.YOURBRAND.com.   A   46.224.98.3

STEP 2 — set gatewayHost = 'proxy.YOURBRAND.com' in EVERY surface that emits a
proxy URL (a missed one falls back to the gw.proxies.sx default):
    new ProxiesClient({ apiKey, proxyUsername, gatewayHost: 'proxy.YOURBRAND.com' });
    createPoolApiHandlers({ ..., gatewayHost: 'proxy.YOURBRAND.com' });   // flows into /me → <PoolPortal>
    <PakQuickstart      gatewayHost="proxy.YOURBRAND.com" ... />
    <PoolSessionSpawner gatewayHost="proxy.YOURBRAND.com" ... />
    <PoolDocsPanel      gatewayHost="proxy.YOURBRAND.com" ... />
  Tip: define ONE constant (e.g. GATEWAY_HOST = 'proxy.YOURBRAND.com') and pass
  it everywhere so none is missed.

VERIFY: a generated proxy string reads
    http://psx_xxx-mbl-us-sid-alice:pak_xxx@proxy.YOURBRAND.com:7000
  and curling through it returns a mobile IP. gw.proxies.sx must appear NOWHERE
  in your UI, copied strings, or docs.

NOTES
- 46.224.98.3 is shared Proxies.sx infrastructure (safe to point DNS at). It is
  NOT a device/exit IP, so this exposes nothing about the proxy pool.
- Username token DSL (unchanged): user-mbl-<country>-carrier-<c>-sid-<id>-rot-<sticky|rotate>
- Reference SDK + full kit docs: https://github.com/bolivian-peru/proxy-reseller-kit
