# Carrier stock and selection fixes — 0.13.1 candidate

Prepared from GitHub `81db33bd187d7b8bf91e5b5cbbb01ab83c1d4256`, the published
0.13.0 SDK/React source. This document describes a candidate, not a publication
receipt. Both npm packages remained 0.13.0 during the September 27 audit.

## Behavior

The React carrier hook and server handler previously always requested peer stock,
even for a modem or combined pool. `usePoolCarrierStock` now accepts an optional
`pool`; the handler forwards `peer`, `mbl` and `all`. The UI/gateway token `any`
normalizes to the stock API token `all`, including the facets hook/handler.
Omitting the argument retains the old peer default. An unrecognized HTTP value
is discarded under the existing whitelist/default policy, never forwarded.
The connected Private Pool picker uses `mbl` for a modem gateway and `all`
otherwise. Counts remain reported inventory, not a reservation guarantee.

The SDK exposes existing optional classification evidence and ASN-count metadata.
The two React carrier controls render that evidence separately from the reported
`ipType`; missing evidence stays unknown. “All carriers / ISPs” is an aggregate
choice, not an unidentified bucket. A selected provider that disappears remains
selected, and Generate/Reserve is disabled until it returns or the customer
explicitly chooses another provider or the aggregate option. The existing ASN,
carrier-name, class and rotation serialization is unchanged. These UI protections
do not repair gateway failover or certify physical cellular/household access.

## Release procedure

The repository has CI, but no trusted automated publish workflow. Follow its
existing manual pnpm release process; verify `npm whoami` without printing tokens.
The September 27 local check returned HTTP 401, so that workstation's publication
credential needs repair before publishing. No token was read or copied.

From the reviewed, frozen checkout:

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm typecheck
(cd packages/sdk && pnpm pack)
(cd packages/react && pnpm pack)
# Inspect both tarball manifests and rerun the clean-install smoke before publishing.
(cd packages/sdk && pnpm publish --access public --no-git-checks)
# Verify the exact SDK version/tarball on the registry before publishing React.
(cd packages/react && pnpm publish --access public --no-git-checks)
```

Use pnpm, not npm, to rewrite workspace dependencies correctly. Read both exact
registry versions/integrities back and install those registry artifacts in a new
project. Tag the reviewed commit only after publication verification. Update the
existing public agents guide/manifests with actual release facts at that point.

Host applications must upgrade both packages and rebuild their server handler
and browser bundle. The first-party `reseller.proxies.sx` admin portal is a separate
Vite app and does not import this hook/handler. The starter templates import the
handler and `PoolPortal`; their default `PoolPortal` does not mount the affected
carrier picker. Custom applications may use the picker, but their deployment
versions were not enumerated or changed by this candidate. Publishing npm alone
must not be reported as updating every reseller installation.
